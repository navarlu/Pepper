# Animation Metadata Experiment

Pipeline for the gesture-metadata study: record every Pepper animation on
video, annotate the clips with a VLM, and produce a rich metadata library
(`animations_metadata.json`) that the voice agent can use for gesture
selection (condition B: metadata) vs. the plain `animations.json` names
(condition A).

## Pipeline

```
robot/data/animations.json
        │
        ▼
1. record_animations.py   — triggers each animation via the bridge
   (RealSense on laptop)    (POST /animation/<name>) and records a fixed
        │                   12 s window per animation → data/recordings/<name>.mp4
        ▼                   + data/recordings_manifest.json (per-clip stats)
2. annotate_videos.py     — motion-detects gesture start/end (duration_s,
   (Gemini, native video)   measured locally), sends the whole clip to Gemini
        │                   with a structured-output schema (short_caption,
        ▼                   communicative_functions, social_tone, body_parts,
data/animations_metadata.json  motion_energy/amplitude/symmetry, speech
   (combined library)          compatibility, dialogue states, avoid contexts,
                               safety notes, confidence) → data/metadata/<name>.json
```

Example metadata entry: see `GestureAnnotation` in `annotate_videos.py`;
`action_id`, `source_label` and `duration_s` are merged in from our side
(`animations.json` + motion detection), not generated by the VLM.

The VLM is **blind to the animation name** so the metadata condition stays
independent of the name condition in the study.

## Usage

```bash
# 0. Smoke-test the camera (5 s clip):
uv run python experiments/animation_metadata/record_test.py

# 1. Record all animations (Pepper + bridge must be running; resumable):
#    Set the bridge address if not tunneled to localhost:
#    PEPPER_BRIDGE_URL=http://<rpi-ip>:5000
uv run python experiments/animation_metadata/record_animations.py

# 2. Annotate the clips (needs GEMINI_API_KEY in .env; resumable):
#    Model override: GEMINI_ANNOTATION_MODEL (default gemini-2.5-flash)
uv run python experiments/animation_metadata/annotate_videos.py
```

For a quick test session set `LIMIT = 3` (or `ONLY = ["Explain_1", ...]`)
at the top of `record_animations.py`.

## Notes / open TODOs

- **Camera:** RealSense D435, color stream only, 1280x720@30. Auto-exposure
  priority is disabled so the fps stays constant (clip timing = real time).
  Use consistent diffuse lighting and a neutral background for all clips.
- **Audio is not captured** — the D435 has no microphone. The noise-level
  metadata (motor noise / embedded sound effects) needs a separate USB mic
  added to the rig, or a second pass.
- Both trigger and capture stats land in `data/recordings_manifest.json`;
  failed triggers are discarded and retried on the next run.
- LED-only animations (`animations/LED/*`) are skipped — nothing to film.
- Sound-bearing `Waiting/*` animations: the bridge mutes `ALAudioPlayer`
  during animations (`bridge.py`), so recordings should be clean; cull the
  non-receptionist ones later during triage anyway.
